# Aequitas Research

Investment-bank-style research reports on public companies, generated by a multi-agent
LLM pipeline — with **zero hallucinated numbers**.

> **Status:** Phase 0 (scaffold). Not yet deployed.

## The guarantee

LLMs in this system never produce figures. Deterministic C# connectors ingest data from
SEC EDGAR into a facts store; agents reference facts by ID (`{{fact:123}}`); and a
validation layer rejects any numeric claim that does not trace back to a stored fact.
Every published report carries a verified-figure count and links to the eval results.

## Architecture

```
[Browser] → [Vercel · Next.js, static-first + ISR]  app.<domain>
                 │ same-site XHR
                 ▼
          [Cloudflare free · WAF, bot fight, rate rules, origin lock]  api.<domain>
                 ▼
          [Azure Container Apps · ASP.NET Core API, scale 0→N]
                 ├──────────────► [Blob Storage: raw / cache / reports]
                 ├──► [Storage Queue: report-jobs] ──KEDA──► [ACA Job · .NET Worker]
                 │                                              agents → Groq / BYOK
                 │                                              connectors → EDGAR, news
                 └──────────────► [PostgreSQL: identity, facts, reports, jobs, quotas]
```

**Read flow (anonymous)** is served entirely from Vercel's CDN — report pages are ISR pages
backed by report JSON, so the API can be asleep and visitors never notice.

**Generate flow (authenticated)** is queued: the API validates quotas, writes a job row and
enqueues a message; KEDA starts the worker, which ingests filings, builds facts, runs the
agents, verifies every figure, and publishes the report. Cold starts hide inside the
progress screen by design.

This split is what makes a $0/month budget compatible with a fast public site — the API
scales to zero, and nothing a visitor touches depends on it being awake.

## Repository layout

| Path | What |
|---|---|
| `frontend/` | Next.js app (App Router, TypeScript, Tailwind) deployed to Vercel |
| `backend/src/Aequitas.Api/` | ASP.NET Core minimal API — auth, reports, jobs |
| `backend/src/Aequitas.Worker/` | Queue-triggered report generator (ACA Job) |
| `backend/src/Aequitas.Core/` | Domain: entities, agent contracts, report schema |
| `backend/src/Aequitas.Infrastructure/` | EF Core, blob/queue clients, connectors, LLM router |
| `backend/tests/` | Unit, integration (Testcontainers + WireMock), and eval suites |
| `infra/` | Terraform (`azurerm`) — all Azure resources |

## Local development

Prerequisites: .NET 10 SDK, Node 22+, Docker (for Testcontainers and Azurite).

```bash
# Backend
dotnet build backend/Aequitas.slnx
dotnet test  backend/Aequitas.slnx --filter "Category!=Eval"

# Frontend
cd frontend && npm install && npm run dev
```

Secrets never live in this repo. Backend config uses `dotnet user-secrets` locally and
Azure Key Vault in production — see [`.env.example`](.env.example) and
`backend/src/Aequitas.Api/appsettings.example.json` for the required shape.
